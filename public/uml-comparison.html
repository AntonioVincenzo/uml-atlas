02 · Relationships

UML behavioral diagrams have their own grammars. Atlas can sketch a few nodes and arrows, but it does not yet represent the semantics needed to call those diagrams UML.

04 · Composition and reuse

Atlas’s most valuable feature is an extension, not standard UML notation

Expandable diagram references solve a real collaboration problem. UML has related mechanisms—packages, package import, structured classifiers, interaction uses, and diagram frames—but no universal “embed any diagram as a node” symbol.

05 · Diagram-family coverage

Current coverage across the UML diagram taxonomy

A node kind is not a diagram type. Atlas’s single graph renderer can approximate parts of four structural/behavioral views; the other UML diagram grammars need purpose-built models.

Class diagram partial

Classes, interfaces, enumerations, members, seven relations. Missing typed features, roles, qualifiers, association classes, templates and constraints.

Component diagram partial

Components and dependencies. Missing ports, parts, provided/required interfaces, assembly and delegation connectors.

Package diagram partial

Package cards and dependencies. Missing containment, merge/import/access semantics and package-qualified ownership.

State machine partial

State cards and transition arrows only; state-machine semantics are not represented.

Use case partial

Actors and use cases have distinct compact forms. System boundaries, include, extend, extension points, and subject semantics are absent.

Object diagram absent

No instance specification, underlined instance notation, slots, or links.

Composite structure absent

No structured classifier, part, port, connector, collaboration or role semantics.

Deployment absent

No UML node, device, execution environment, artifact, deployment or communication path.

Profile absent

Free-text stereotypes exist, but profiles, stereotype definitions, extensions and tagged values do not.

Activity absent

No actions, control/object flows, pins, partitions, decisions, forks, joins or object nodes.

Sequence absent

No lifelines, message occurrences, executions, fragments, gates, state invariants or time ordering.

Communication absent

No interaction messages, sequence expressions or connector-bound communication semantics.

Interaction overview absent

No interaction-use flow grammar or activity-style control nodes.

Timing absent

No time axis, state/condition timelines, duration constraints or time observations.

06 · Recommended path

Increase fidelity without sacrificing Atlas’s agent-first design

The quickest route is to make the existing structural editor honest and precise, then add diagram-specific models only where users need them.

1

Complete the visual grammar

Class and enumeration compartments, stereotype-first titles, compact actors/use cases, and unlabeled notes are implemented. Add ports and provided/required interface notation, then make association non-directed by default.

2

Split model concepts from visual shortcuts

Represent attributes, operations, enumeration literals, stereotypes, tagged values, navigability, role names and transition trigger/guard/effect as structured JSON instead of free text.

3

Add strictness as a selectable profile

Keep permissive architecture graphs, plus a UML-strict mode that constrains valid endpoints and relationship use. Agents can ask validation for a chosen profile before proposing.

4

Build component/composite structure next

Ports and provided/required interfaces yield the greatest architecture value. They connect system boundaries to code regions better than adding every UML classifier first.

5

Give behavior separate schemas

State machine, sequence and activity diagrams need their own element unions and validators. Do not force lifelines or control nodes into the current generic node/edge schema.

6

Offer standard interchange

Map the strict subset to UML 2.5.1 XMI and Diagram Interchange. Preserve Atlas-only data in a profile or sidecar so code links, stable diffs and diagram references survive.

Sources and interpretation

The normative baseline is the OMG Unified Modeling Language 2.5.1 specification, with the official specification index and machine-readable metamodel/diagram-interchange files. The diagram taxonomy is also summarized by OMG’s UML overview.

“Proper UML” here means conventional notation backed by UML model semantics. UML permits presentation variation and mixed diagrams, so the audit does not treat cosmetic variation alone as a defect. It focuses on differences that imply, omit, or blur meaning.

Atlas evidence inspected

src/core/model.ts defines 11 node kinds and 7 edge kinds. src/ui/Canvas.tsx renders classifier compartments, compact actor/use-case nodes, notes, generic stereotyped nodes, and relationship markers. src/core/uml.ts defines the PlantUML-style textual subset. docs/UML.md explicitly lists unsupported syntax and semantics.

This report describes Atlas 0.1 as built in this workspace. It is an engineering audit, not a certification by OMG. “Close” means visually and directionally recognizable for the represented subset; it does not claim full metamodel conformance.
